# One-Button Game Benchmark

Build the best original browser game you can.

You are competing against other AI models. Every model receives the same challenge.

## Your Workspace

You have been assigned your own directory in this repository.

You may **create, modify, and delete files inside your assigned directory only**.

Do not modify:

- The repository root
- `README.md`
- Files belonging to another model
- Any other directory

Your game must run from:

`/<your-directory>/index.html`

Your directory must contain everything required to run your game.

Your directory must also contain a `README.md` that briefly explains:

- What the game is
- How the one-button control works
- What the player is trying to do

## The Challenge

The player has exactly **one control**:

- **Desktop:** `Space`
- **Mobile:** tap anywhere on the game
- **Mouse:** click anywhere on the game

All three inputs must perform the **same action**.

You decide everything else.

Invent the:

- Concept
- Game mechanics
- Objective
- Visual style
- Progression
- Scoring
- Feedback
- Sound
- Difficulty
- Game feel

## Technical Constraints

- Static website only
- Must work when hosted on GitHub Pages
- No backend
- No external APIs
- No authentication
- No external assets required
- Use HTML, CSS, and JavaScript
- Must work on desktop and mobile
- Must be playable immediately after loading
- Restart must be possible using the same single control
- Entry point must be `index.html` in your assigned directory
- Include a `README.md` in your assigned directory describing the game and controls

## Game Constraints

The game must:

- Be understandable without reading instructions
- Give immediate feedback to the player's action
- Have meaningful failure, success, scoring, or progression
- Derive interesting gameplay from the timing or context of its single action
- Reward mastery rather than random input
- Feel polished and responsive

Do not clone an existing game.

## Your Freedom

Everything not explicitly constrained above is your decision.

Creativity is part of the benchmark.

Do not ask questions.

Do not explain what you intend to build before building it.

Make your own creative decisions.

**Build the game.**

When you believe it is complete, play-test it and fix any obvious gameplay, input, mobile, layout, performance, or restart problems.
